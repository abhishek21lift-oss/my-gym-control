| Node | ≥ 22 | Developed on 26.1 |

| Docker | any recent | Postgres 18, Redis 8, MinIO for local infra |

## Getting started

```bash
pnpm install
```

```bash
cp .env.example .env
```

```bash
pnpm infra:up
```

```bash
pnpm db:migrate
```

```bash
pnpm dev
```

The API is then on `http://localhost:4000`. Verify it:

```bash
curl http://localhost:4000/api/v1/health/ready
```

Expected:

```json
{ "status": "ok", "checks": { "database": { "status": "up", "latencyMs": 3 } } }
```

## Workspace

```
apps/api          NestJS modular monolith
packages/contracts Zod schemas + inferred types shared by API and frontends
packages/db        Prisma schema, migrations, tenant context
```

`apps/app` (all authenticated portals), `apps/web` (public site), `apps/worker`
(BullMQ consumers) and `packages/ui` land in the phases that need them — see the
roadmap.

## Commands

| Command | Does |
|---|---|
| `pnpm dev` | Runs every app in watch mode |
| `pnpm build` | Builds everything, in dependency order |
| `pnpm typecheck` | Typechecks every package |
| `pnpm test` | Unit tests |
| `pnpm db:migrate` | Creates and applies a migration |
| `pnpm db:studio` | Prisma Studio |
| `pnpm infra:up` / `infra:down` | Local Postgres, Redis, MinIO |
| `pnpm infra:reset` | Destroys local data and starts clean |

## Things worth knowing before you change something

**Never write `organizationId` in a query.** Tenant scoping is injected by a Prisma
client extension reading `AsyncLocalStorage`. If you find yourself passing an
organization id into a repository, something upstream is wrong. See
[ARCHITECTURE §4](docs/ARCHITECTURE.md).

**Dependency versions live in `pnpm-workspace.yaml`**, under `catalog:`. Packages
declare `"react": "catalog:"`. Do not pin a version inside a package's `package.json` —
that is how two copies of React end up in one bundle.

**Money is an integer.** Amounts are stored in the currency's minor unit (paise,
cents) alongside an ISO-4217 code. Floating point never touches a monetary value.

**Ids are UUID v7**, generated by Postgres. `uuidv7()` is native on Postgres 18; the
first migration installs a pl/pgsql equivalent when running against 16/17 (including
current Supabase), so the schema applies either way.

**TypeScript is pinned to 5.9.3** workspace-wide, even though 7.x is `latest`.
`@nestjs/cli` pins exactly 5.9.3 and NestJS DI depends on `emitDecoratorMetadata` from
the classic compiler.
